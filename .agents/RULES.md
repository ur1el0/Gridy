# Gridy - Global Development Rules

These rules apply universally to all agents and developers working on the Gridy project.

## 1. Code Quality & Formatting
- **Python (Backend)**: Follow PEP 8 guidelines. Remove unused imports before committing. Use explicit relative imports where necessary.
- **TypeScript (Frontend)**: Strict type-checking is enforced. Avoid `any` types. Use standard functional components.

## 2. API & Data Contracts
- The Django Backend is the ultimate source of truth.
- Frontend must rely on the OpenAPI schemas generated by DRF.
- When changing a model, the DRF Serializer MUST be updated to reflect field changes accurately.

## 3. Database Safety
- **No Raw SQL**: Always use the Django ORM.
- **Migration Safety**: Never manually edit database schemas. Always use `python manage.py makemigrations` and `python manage.py migrate`.
- **Container Awareness**: Migrations must be generated/applied against the running Docker database, not the host machine's isolated SQLite instances.

## 4. UI/UX Standards
- Enforce premium, responsive aesthetics using Tailwind CSS.
- Include micro-animations (e.g., hover states, transitions) to enhance user interactivity.
- Follow Web Accessibility (a11y) standards: semantic HTML and ARIA labels.

## 5. Agent Constraints
- **Teaching over Telling**: AI Agents must prioritize explaining concepts over dumping code blocks.
- **User Code Entry**: The AI MUST NOT edit the user's source code directly for feature work. Provide snippets for the user to type manually to build muscle memory.
- **No Unsolicited Pushes**: Never push directly to `main`. Always use `feature/` branches and PRs.
